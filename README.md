# NunKil

저시력·시각장애인을 위한 Ray-Ban Meta 보조 앱. 소리가 인터페이스이고, 화면을 보지 않고 모든 기능을 쓸 수 있는 것이 기준이다.

먼저 만드는 것은 두 가지다.
- **상품 식별과 가격** — 손에 든 과자·음료가 무엇인지 1~2초 안에 말해주고, 매대 가격과 온라인 최저가를 비교한다.
- **접근 위험 감지** — 다가오는 차·오토바이·자전거를 온디바이스에서 감지해 즉시 알린다.

## 이 앱이 하지 않는 것

- **흰지팡이·안내견·보행 훈련을 대체하지 않는다.** 보조 수단이다.
- 안경 카메라는 **앞만 본다.** 뒤나 옆에서 오는 차는 보이지 않는다.
- **야간·저조도에서 성능이 크게 떨어진다.**
- 사람의 외모나 행동으로 위험인물을 판별하지 않는다. 오탐이 무고한 사람을 지목하고 편향이 그대로 드러나기 때문이다.
- Meta AI와 Be My Eyes가 이미 잘 하는 주변 묘사·글자 읽기·자원봉사자 연결은 다시 만들지 않는다.

## 구조

```
iPhone 앱 (ios/)  ──BLE/Wi-Fi──  Ray-Ban Meta
      │
      ├─ 온디바이스: 바코드, 글자 인식, 접근 감지   ← 여기서 끝나면 사진은 폰 밖으로 나가지 않는다
      ▼
백엔드 (src/nunkil) ──▶ Yahoo!ショッピング / 楽天 / 네이버 쇼핑
```

안경 연결·스트림·음성 출력은 [glasseskit](../glasseskit) 패키지를 공유한다.

**바코드가 읽히면 사진을 전송하지 않는다.** 앱이 폰에서 바코드를 읽고 번호만 조회하므로 빠르고, 사진이 밖으로 나가지 않는다. 바코드가 없을 때만 글자 인식 → 그래도 모호하면 이미지 기반 모델을 쓴다.

## 백엔드 실행

```sh
uv sync
uv run pytest                       # API 키 없이 전부 통과한다
set -a; source .env; set +a          # .env 는 gitignore 된다
uv run nunkil
```

| 환경변수 | 쓰임 |
|---|---|
| `NUNKIL_TOKEN` | 앱과 공유하는 접근 토큰. 없으면 서버가 뜨지 않는다 |
| `YAHOO_CLIENT_ID` | 일본. Yahoo!デベロッパー의 Client ID(アプリケーションID). **JAN 바코드를 직접 조회할 수 있는 유일한 공급자** |
| `RAKUTEN_APP_ID`, `RAKUTEN_ACCESS_KEY` | 일본, 가격 비교용 보조 |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 한국 |

지역별로 키가 있는 공급자만 사용한다. 키가 없는 지역을 조회하면 503과 함께 **필요한 환경변수 이름**을 돌려준다.

## 안경 없이 기여하기

이 프로젝트의 판정 로직은 하드웨어 없이 개발·검증할 수 있게 두는 것을 원칙으로 한다.

- 백엔드 테스트는 모의 HTTP 전송 계층을 써서 API 키 없이 전부 돈다.
- 앱의 온디바이스 판정(흐림·바코드·접근 감지)은 순수 함수라 합성 이미지로 테스트한다.
- 안경 연결이 필요한 흐름은 Meta의 MockDeviceKit에 합성 HEVC 영상을 넣어 시뮬레이터에서 돌린다.
